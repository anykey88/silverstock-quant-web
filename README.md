**台股实战工作站：选股、价位、时机、部位**

> 在线体验（公网 HTTPS）：<https://a45673301cf901233.app.workbuddy.host/?sharecode=EJYVNROLHG>
> 建议用 iPad mini（Safari 竖屏 / 横屏）或手机打开；电脑浏览器同样可用。

## 只有一个版本（v2.2 起）

早期做过双版本，v2.2 已全部移除：功能永久开启，没有可切换的第二套口径，界面上也不再插入任何警语横幅。

目标很直白——**把选股、价位、时机、部位四个环节做成能直接照着执行的东西**。判断依据全部摊开（评分拆解、估值分位、条件概率），结论自己下。

### 刻意不做的三件事（以及替代方案）

| 不做 | 为什么 | 改用什么 |
| --- | --- | --- |
| 预测大盘涨跌 | 没人能稳定预测；做出来只会给你错误信心 | **市场温度**（位阶/广度/量能/波动四合一）+ **历史条件概率**（过去处在同样条件时，之后 20/60 日的报酬分布） |
| 个股推荐 / 目标价 | 目标价无法验证——给了你也无从判断它对不对 | **五维评分 + 逐条理由**，把判断依据摊开，你自己决定 |
| 「下一波行情的买卖点」 | 事后看线很容易，事前不可能；给点位本质是猜测 | **条件提醒**（到你自己设的价格/殖利率才提示）+ **模拟交易盘**练手 |

> 这三项即使你自己用也不会加：不是保守，是它们**在方法上就不成立**。给了反而害你。

## 一、项目简介

台股指数从万点一路走到接近五万点，很多台湾退休长辈把「存股领息」当成退休生活的一部分。但市面上的台股分析、量化回测工具，术语多、字体小、按钮密，长辈点两下就放弃了。

**SilverStock-Quant-Web 只做三件事，并把三件事做到长辈能自己用：**

1. **看得懂**：繁体中文、大字、高对比、按钮至少 60px 高，iPad mini 上开箱即用，不需要双指缩放。
2. **听得懂**：输入可以用「说」的（例如「用高殖利率策略回测台积电过去 5 年」），报告可以一键用**国语 / 台语**朗读。
3. **说得清**：5 个 Agent 依序协作，把财报、技术指标、历史回测翻成台湾大白话，输出前由 Agent 5 做一次用词与数值一致性检查。

**它明确不做的事**：不预测股价、不给买卖点位、不接券商、不下单、不看实时行情。

## 三、WorkBuddy 5 个 Agent 分工

前端只负责 UI 与交互，业务逻辑由 5 个 Agent 依序完成；每次请求都会**完整跑完 5 步**，第 5 步不可跳过。

| # | Agent | 输入 | 输出 | 边界（强制） |
| --- | --- | --- | --- | --- |
| 1 | **基本面解析 Agent** | 股票代码、时间区间 | 殖利率、本益比、股价净值比、年度 EPS、配息记录、风险检核清单（JSON） | 只做客观整理，不输出任何投资判断 |
| 2 | **技术指标 Agent** | 历史行情 | MA5/20/60、KD(9)、RSI(14)、MACD(12,26,9) 数值 | 只给数值，**不输出买卖信号**，冷门指标一律不实现 |
| 3 | **量化回测 Agent** | 行情 + 策略模板 | 历史年化（IRR）、最大回撤、年度胜率、净值曲线、三策略横向对照 | 只做历史模拟，不预测；图表强制水印「历史回测不等于未来收益」 |
| 4 | **适老化翻译 & 语音播报 Agent** | 上述结构化结果 | 台湾大白话报告 + 语音播报稿（可用国语/台语 TTS 朗读） | 只用生活化说法，不新增结论 |
| 5 | **输出检查 Agent** | 全部输出文本 + 播报稿 | 最终文本 | v2.2 起原文放行：不改写、不附加声明、不拦截 |

### 调用顺序与可视化

```
用户请求（文字 / 语音）
   ↓  QueryParser 解析（股票、策略、年数；命中高危词直接拦截）
① 基本面解析 → ② 技术指标 → ③ 量化回测 → ④ 白话翻译 → ⑤ 输出检查
   ↓
页面渲染：大字摘要 / 极简回测曲线 / 大白话报告 / 语音播放 / 本机存档
```

界面上有一个 **Agent 协作面板**，会实时显示 5 个 Agent 的状态（等待 / 执行中 / 完成 / 拦截）与每步摘要，长辈可以直观看到「现在是第几步」。

### 关于「后端 Agent 接口」

正式架构是「前端 HTTP 调用 WorkBuddy Agent 集群」。为了让公网链接**不依赖任何私有后端**，同一套 Agent 流程做成了**前端同构运行时**（`lib/agents/agents.dart`），数据契约完全一致；只要通过编译参数指定网关，即可切换为远端调用：

```bash
flutter build web --dart-define=AGENT_ENDPOINT=https://your-workbuddy-gateway.example.com/agents
```

`AgentGateway.endpoint` 读取该参数，前端即可把同一份请求 JSON 发往远端 Agent 集群。目前未部署远端网关，默认使用本地同构运行时。

- 本 Demo 使用 **FinMind 公开历史数据 API v4**（数据集：`TaiwanStockPrice`（含每日成交量）、`TaiwanStockPER`、`TaiwanStockDividend`、`TaiwanStockFinancialStatements`；另抓 `TAIEX` 加权指数全期资料）。
- 为避开免费额度与跨域限制影响演示稳定性，数据在**建置期抓取为快照**（`assets/data/snapshot.json`，33 档 + 加权指数、抓取日 2026-10-24、覆盖 2021-06-01 ～ 2026-10-22、约 1 MB），网页运行时读取本地快照，不发起第三方请求。
- 数据清洗如实记录在 `snapshot.json` 的 `meta.cleaning` 字段：
  1. 收盘价为 0 的缺值以前一交易日递补；
  2. 已做**股票分割回溯调整**（0050 于 2025-06-18 进行 1 分 4，历史价格与股利同步除以 4）；
  3. **未做股利还原**（股利以现金单独计入回测，不假设再投入）。
- 抓取脚本：`tool/fetch_snapshot.py`；校验脚本：`tool/check_backtest.dart`。

## 五之二、v2.0 新增：名称搜索与每日精选

### 1. 名称搜索（不必先知道代号）

输入框接受三种输入，判断顺序是固定的：

| 输入 | 处理方式 |
|---|---|
| 已载入过的代号（如 `2330`） | 直接选中，零延迟 |
| 形如代号的字串（4–6 位数字 + 可选英文字尾） | 走线上建档流程 |
| 其余一律当名称搜 | 全市场 3171 档模糊比对 |

这样「2330」不会被当名称去搜，「台积」也不会被误判成代号。

**简繁互通**：索引里每档同时存繁体名与简体名，另附一张 390 字的「繁→简」字元对照表。查询字串先正规化成简体，再与简体名比对，所以在大陆用简体输入法打「台积电」「鸿海」「中华电」都找得到。

**排序不是「符合就好」**，而是分五级：代号完全相同 > 名称完全相同 > 代号前缀 > 名称前缀 > 名称包含 > 产业包含；同级时上市优先于上柜、上柜优先于兴柜，非 ETF 优先，名称短的优先。

索引档 `assets/data/stock_index.json`（184KB，3171 档）随 App 打包，打开就载入，不打任何 API。重建方式：

```bash
pip install opencc-python-reimplemented
python3 tool/v2/build_index.py
```

### 2. 每日精选：两份名单，八个数字，一个原则

**原则：名单回答的是「哪些股票符合我设定的条件」，不是「该买哪一支」。**

#### 买进观察（前 10）

先过四道硬门槛，任何一条不过就直接剔除、不进排名：

| 门槛 | 数值 | 为什么设这条 |
|---|---|---|
| 日均成交额 | ≥ 0.5 亿 | 低于此进出的滑价会吃掉报酬 |
| 财务底线 | 近四季 EPS 合计 > 0、负债比 ≤ 80% | 两条谁都不该违反的线；不用「财务检核总分」当门槛，那会把鸿海、广达这类正常公司误杀 |
| 近 3 月营收年增 | ≥ -20% | 不在营收崩跌时接刀 |
| 本益比历史百分位 | ≤ 85% | 再好的公司，贵到极端也不追 |

过了门槛后按四项加权：

| 项目 | 权重 | 算法 |
|---|---|---|
| 财务品质 | 30% | 财务检核分数（ROE、毛利率、负债比、现金流、周转天数等十余项） |
| 估值便宜度 | 30% | `(100 − 本益比历史百分位) / 100 × 30` |
| 殖利率 | 20% | `min(殖利率 / 6%, 1) × 20`，6% 封顶 |
| 营收动能 | 20% | 连续正成长月数与 3 月均年增率各半 |

#### 减码观察

**不受买进门槛限制**，全候选池一起排名，门槛 15 分：

| 项目 | 权重 | 触发条件 |
|---|---|---|
| 估值极端 | 30% | 本益比百分位 > 70 起算，> 90 满分 |
| 动能转弱 | 25% | 处于「成长放缓」或「营收衰退」阶段 |
| 营收转负 | 10% | 月营收年增为负 |
| 财务恶化 | 20% | 财务检核 < 60 分 |
| 距高点回落 | 15% | 从 52 周高点回落 > 20% |
| 股利衰退 | 10% | 最近一年现金股利较前一年减少 > 10% |

> 名单**宁可空着，也不硬凑十档**。「今天没有该减码的」本身就是有用的结论。

#### 价格区间为什么叫「估值合理区」

一开始我用「本益比 20~40 百分位反推」当买进区间，结果是台积电算出 1,600 元、鸿海算出 159 元——现价 2,415 和 248，**永远等不到**。那种数字看起来保守，实际是把「不会发生」包装成「纪律」。

现在改成三档：

| 区间 | 算法 |
|---|---|
| **估值合理区** | 下缘 = 本益比 30 百分位（或殖利率 5.5% 反推，取较严）；上缘 = 本益比 55 百分位（或殖利率 4.2%，取较严） |
| **减码区间** | 本益比 80~92 百分位（或殖利率 3.2%／2.6% 反推） |
| **现价位置** | 明确写出「高于上缘 X%」或「已在区间内」 |

两种方法（本益比 vs 殖利率）差距在 35% 以内才互相校正，否则视为其中一种失效、只取本益比法并标注。

每一档都会写明**区间推算依据**与**失效条件**，例如：

- 金融股：本益比逻辑不适用（损益受利率与提存影响大），应以股价净值比为主
- EPS 为负或缺失：改用季线法，可信度较低
- 估值样本 < 250 天：分位数代表性不足
- 产业发生结构性变化（新技术替代、政策转向）：历史分位会失效

#### 没被选中的，也有解释

页面上有一块「这次没列入买进名单的 N 档」，逐条写原因，例如：

```
南亚科 2408   近 3 月营收年减 26%，超过 -20% 门槛
群创 3481     日均成交额仅 0.31 亿，低于 0.5 亿门槛
友达 2409     负债比 82%，超过 80% 底线
联发科 2454  本益比位于近 3 年 88 百分位（门槛 85），属绝对高档不追价
```

使用者最常问的是「为什么我那档没在裡面」，与其让人猜，不如直接给答案。

### 3. 为什么不做全市场扫描

FinMind 免费额度是**逐档计费**：一档股票要 4 个日常数据集 + 3 个财报数据集，合计 7 次请求。全市场 2,000 档 = 14,000 次请求，而匿名额度只有 300 次／小时、注册 600 次／小时。

所以做两件事：

1. **固定候选池**（116 档，覆盖台股市值绝大部分）：`tool/v2_scan.dart` 里的 `candidatePool`
2. **财报快取 30 天**：财报一季才变一次，没必要每天重抓。日常扫描每档只需 4 次请求

使用者自己的自选股不在这里扫描，由前端在本机用同一套引擎计算——这样既不消耗额度，也不需要把持股上传到任何地方。

### 4. 名單怎麼產生、多久更新

| 环节 | 做法 |
|---|---|
| 触发 | GitHub Actions，每交易日台北时间 14:30（`cron: '30 6 * * 1-5'`） |
| 执行 | `dart run tool/v2_scan.dart --out assets/data/daily_picks.json` |
| 产出 | 提交回 `main`，自动触发 Pages 部署，当天网站就更新 |
| 手动跑 | `dart run tool/v2_scan.dart --limit 10 --delay 6200` |

正式跑全池请在 repo secrets 里设 `FINMIND_TOKEN`（免费注册即可，额度从 300 提到 600 次／小时）。

### 5. 局限（写在最前面，不藏在最后面）

- 只有公开财务与价量资料，**没有法人预估、订单能见度、经营层访谈**
- 免费 API 拿不到**还原股价**，除权息调整是自行推算的
- 财报有公布时滞（季报最晚季末后 45 天），最近一季的数字可能还没进来
- 评分是**横截面比较**，不是时间序列预测：它说「A 比 B 便宜」，不说「明天会涨」

## 五之三、v2.1 新增：多账户管理与组合风险体检

### 1. 为什么「一个账户」不够用

投资从来不是一个人的事。父母的退休金要现金流与保本，配偶的存股要稳定配息，
你的波段部位要成长，还有一个专门用来试错的练习账户——它们的**目标、风险承受度、
持有期间完全不同**。混在一起算，只会得到一个谁都不满意的平均数。

v2.1 把原本写死的单一模拟盘，改成**账户数量不限的多本账册**：

| 能力 | 说明 |
| --- | --- |
| 自定义名称 | 「爸爸」「老婆」「练习一号」「妈妈的退休金」都可以，中英文不限 |
| 两种性质 | **真实账户**＝记账（券商成交后回填）；**模拟练习**＝虚拟资金验证策略 |
| 各自独立 | 各自的本金、现金、流水、持仓，互不污染 |
| 切换操作 | 首页「投资账户」→ 点「使用」进入该本记账，顶部胶囊条可随时换 |
| 导出 | 单本汇出／全部汇出，CSV（UTF-8 含 BOM），Excel 与 Google Sheets 直接开 |
| 旧数据 | v2.0 的模拟盘数据自动搬成「练习帐（v2.0 旧资料）」，一笔不丢 |

**刻意不做**：不串接券商、不自动抓对账单、不同步云端。台股券商 API 不对个人开放；
家人的持股属于敏感信息，不该离开这台装置。

### 2. 组合风险体检：八个指标，一个分数

「买了什么」大家都看得到，「**这个组合会在哪里出事**」很少人算。v2.1 新增的体检
只做结构性诊断，**不预测涨跌、不给买卖点**：

| 指标 | 为什么看这个 |
| --- | --- |
| 最大单一持股 | 台股散户最常见的死法是重压一档自己最熟的公司 |
| 前三大合计 + HHI | 等效持股数，判断「你以为分散了没」 |
| 最大产业占比 | 台股电子权重高，很容易「买了 8 档、7 档同一个景气循环」 |
| 加权年振幅 | 用 52 周高低价估算，比标准差更贴近体感 |
| 距 52 周高点 | 存股族真正的痛点不是波动，是「抱了一年还在亏」 |
| 加权估值位阶 | 本益比百分位加权，判断「未来的报酬是不是被先借走了」 |
| 现金比重 | 空手也是一种部位；满仓的人崩盘时只能看着 |
| 减码名单冲突 | 你持有的股票正好在系统减码名单上，值得看一眼理由 |

分数（0–100，越高越脆弱）不是投资建议，而是**「依赖少数几个假设」的程度**。
分数低不等于会赚钱，只代表「出错时不会一次全错」。

体检下方会给出 3–5 条**具体的、可执行的观察**（不是指令），例如：

> 台积电占 41.2%。如果你当初设定的上限是 20%，现在是「获利把它推上去」还是
> 「你一直加码」？前者叫纪律失守，后者叫信念加码——两者处理方式完全不同。
